= A hypermedia API derived from a schema

One EDN file names the resources, their fields and how they relate. The tables,
the indexes, the routes, the links and the documents are derived from it and
served over JDBC. Nothing is written per resource.

== Run it

[source,shell]
----
java -jar target/uberjar/hypermedia-standalone.jar \
  --schema example.edn \
  --database 'jdbc:h2:mem:demo;DB_CLOSE_DELAY=-1' \
  --migrate --port 8181
export BASE=http://127.0.0.1:8181
----

| option | meaning
| `-s --schema`      | a file, or something on the classpath
| `-d --database`    | the jdbc url, which also picks the engine
| `-p --port`        | 8080; zero binds any port and announces the one it got
| `-h --host`        | 127.0.0.1
| `-c --connections` | most connections to hold open
| `--connection-timeout` | how long to wait for one
| `--drain`          | how long to let requests finish when stopping; 10s
| `--quiet`          | do not log requests
| `--migrate`        | bring the store to the schema before serving
| `--plan`           | print what a migration would do, and do nothing

`java -jar hypermedia-standalone.jar -- --help` lists them.

== The schema it serves

.resources/example.edn

[source,clojure]
----
{:curie "rel"
 :resources
 {:author {:fields    {:id   {:type :uuid :identity true :generated true}
                       :name {:type :string :required true}}
           :relations {:books {:kind :has-many :target :book :via :author-id}}
           :searches  {:by-name {:predicates [:name]}}}
  :book   {:fields      {:id        {:type :uuid :identity true :generated true}
                         :title     {:type :string :required true}
                         :year      {:type :long}
                         :author-id {:type :uuid}}
           :relations   {:author {:kind :belongs-to :target :author :via :author-id :embed true}}
           :projections {:summary {:fields [:title]}
                         :full    {:fields [:title :year] :embed [:author]}}
           :searches    {:by-title {:predicates [:title]}
                         :by-year  {:predicates [:year]}}}}}
----

== Walk it

Everything below runs as written; generated ids will differ. Start at the root:

[source,shell]
----
$ http GET http://localhost:8181/
----

[source,json]
----
{
  "self": {"href": "/"},
  "profile": {"href": "/profile"},
  "rel:health": {"href": "/health"},
  "rel:authors": {"href": "/authors"},
  "rel:books": {"href": "/books"},
  "curies": [{"name": "rel", "href": "/profile/{rel}", "templated": true}]
}
----

Create an author:

[source,shell]
----
$ http POST $BASE/authors name="Ursula Le Guin"
----

[source,json]
----
{
  "name": "Ursula Le Guin",
  "_links": {
    "self": {"href": "/authors/..."},
    "profile": {"href": "/profile/authors"},
    "rel:books": {"href": "/authors/.../books"}
  }
}
----

Create a book against it. A client writes what it read: the relation takes the
link, not the key. `author` is declared `:embed`, so it comes back embedded.

[source,shell]
----
$ http POST $BASE/books author=/authors/... title="A Wizard of Earthsea" year:=1968
----

[source,json]
----
{
  "title": "A Wizard of Earthsea",
  "year": 1968,
  "_links": {
    "self": {"href": "/books/..."},
    "profile": {"href": "/profile/books"},
    "rel:author": {"href": "/books/.../author"},
    "rel:projection": {"href": "/books/...{?projection}", "templated": true}
  },
  "_embedded": {
    "author": {
      "name": "Ursula Le Guin",
      "_links": {"self": {"href": "/authors/..."}}
    }
  }
}
----

Add two more books:

[source,shell]
----
$ http POST $BASE/books author=/authors/... title="The Tombs of Atuan" year:=1971
$ http POST $BASE/books author=/authors/... title="The Farthest Shore" year:=1972
----

A collection is a slice. `next` is a link to follow, not a URL to build.

[source,shell]
----
$ http GET "$BASE/books?size=2&sort=title,asc"
----

[source,json]
----
{
  "page": {"size": 2, "totalElements": 3, "totalPages": 2, "number": 0},
  "_links": {
    "self": {"href": "/books?size=2&sort=title,asc"},
    "next": {"href": "/books?page=1&size=2&sort=title,asc&after=..."}
  },
  "_embedded": {
    "books": [
      {"title": "A Wizard of Earthsea", ...},
      {"title": "The Farthest Shore", ...}
    ]
  }
}
----

A declared search is a resource, and so is a relation.

[source,shell]
----
$ http GET "$BASE/books/search/by-year?year=1971"
$ http GET "$BASE/authors/.../books"
----

[source,json]
----
["The Tombs of Atuan"]
["A Wizard of Earthsea", "The Tombs of Atuan", "The Farthest Shore"]
----

A read carries an `ETag`. A write naming it is admitted once; the same tag a
second time has gone stale and is refused rather than merged.

[source,shell]
----
$ http GET $BASE/books/...
ETag: "0"

$ http PATCH $BASE/books/... If-Match:"0" year:=1969
→ 200 OK, year updated

$ http PATCH $BASE/books/... If-Match:"0" year:=1970
→ 412 Precondition Failed
----

A submission that does not fit the schema is a problem document (RFC 9457).

[source,shell]
----
$ http POST $BASE/books year:=1968
----

[source,json]
----
{
  "type": "about:blank",
  "title": "the submission does not fit the schema",
  "status": 422,
  "instance": "/books",
  "errors": [{"field": "title", "error": "missing"}]
}
----

Also served:
- `/health` — reports the store, not its own handle
- `/profile/books` — ALPS descriptor
- `Accept: application/prs.hal-forms+json` — adds `_templates` for forms
- `OPTIONS` — answers `Allow`
- `?projection=summary` — narrows a document

== Watching it

Every answer carries `X-Request-Id`. One the caller brought is kept, so a
gateway's identifier follows the request through; otherwise one is minted.
The same identifier names the request in the log.

[source,shell]
----
from-the-gateway GET /books 200 1ms
3c247fa9-f72 POST /books 422 22ms
3ffc0632-773 GET /books/nope 404 1ms
----

Stopping lets requests in flight finish first, for as long as `--drain` allows.

== The schema language

[cols="1,3"]
|===
| key | what it holds

| `:fields`
| name -> `{:type :identity :generated :required :indexed :column}`

| `:relations`
| name -> `{:kind :target :via :through :target-via :embed}`

| `:projections`
| name -> `{:fields :embed}`, chosen with `?projection=`

| `:searches`
| name -> `{:predicates}`, served under `/<collection>/search/`

| `:collection` `:table`
| override the names derived from the resource key

| `:curie`
| prefix for invented relations, or `false` to decline it
|===

Field types: `:uuid :string :text :long :double :decimal :boolean :instant :date`.
Relation kinds: `:belongs-to :has-one :has-many :many-to-many`. The columns a
schema searches, sorts or follows are indexed when the tables are derived.

A many-to-many names the table between the two resources and the column in it
that addresses each side. Both sides describe the same table, mirrored, and it
is derived once:

[source,clojure]
----
:author {:relations {:books {:kind :many-to-many :target :book
                              :through :authorship :via :author-id :target-via :book-id}}}
:book   {:relations {:authors {:kind :many-to-many :target :author
                                :through :authorship :via :book-id :target-via :author-id}}}
----

`resources/catalogue.edn` is a complete one.

A schema is read at boot from a file or the classpath. It can instead be
expanded at compile time, which makes the model, the routes and the statements
constants, and turns an invalid schema into a build failure:

[source,clojure]
----
(hypermedia.api/defapi shop {:resources {...}})
----

== Paging

A collection is ordered by what `sort` asks for, and then by its identity, so
the order is total and a page never repeats or skips a row. `next` carries an
opaque cursor; following it continues from the last row rather than counting
past the ones before it. Measured against a hundred thousand rows, page four
thousand costs 1.2 ms by cursor against 45 ms by offset, and the first page
costs 1.1 ms.

A cursor belongs to the ordering it was made for. Sent with a different
`sort`, it is refused rather than quietly ignored.

== Changing the schema

Add a field, redeploy with `--migrate`, and the store is brought to the
schema: tables and columns it lacks are added, indexes are ensured, and rows
already written are left alone.

What it will not do is guess at something destructive. A column the schema no
longer declares is reported, never dropped; a column whose type no longer
matches is reported; a required column cannot be added to a table that already
holds rows. On any of those the platform refuses to start rather than serve a
schema the store cannot meet.

Paging deep into a collection costs what the first page costs, so long as the
client follows links: `next` carries a cursor naming the row it left off at,
and the query continues from there rather than counting past what it skipped.
A client that builds `page=N` itself still gets the right answer, and still
pays for the offset.

`--plan` prints what a migration would do and does nothing:

[source,shell]
----
$ java -jar hypermedia-standalone.jar \
  --schema example.edn --database 'jdbc:h2:file:./store' --plan
----

[source,shell]
----
CREATE TABLE IF NOT EXISTS "books" ADD COLUMN "tag" VARCHAR(255)
refused: books.year type-differs (schema says string, store holds bigint)
----

It exits non-zero when anything is refused, so a deployment can ask first.

Instances starting together are safe: a migration applies its plan, reads the
store back, and is finished only when nothing is left to do, so a failure that
only means another instance got there first is retried rather than fatal.

== Package it

[source,shell]
----
lein uberjar
java -jar target/uberjar/hypermedia-standalone.jar \
  --schema example.edn --database 'jdbc:h2:mem:demo;DB_CLOSE_DELAY=-1' \
  --migrate --port 8181
----

The jar carries every engine below, so it needs nothing but a JVM. A schema is
read from the filesystem if it is there and from the jar if it is not.

== Engines

The JDBC url picks the engine: H2, PostgreSQL, MariaDB or MySQL, HSQLDB, Derby,
SQLite. Types, paging syntax, identifier quoting and the values a driver will
accept differ per engine and are handled per engine. The same scenarios run end
to end against all six.
